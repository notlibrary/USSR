# usa — refinement ideas

**Today:** a C99 compiler written in USSR. The pipeline is `cpp.su`
(preprocessor), `lex.su`, `parse.su` + `expr.su` (recursive descent
with lowered nodes) and `gen.su` (VM bytecode, link, `.ru` writer). It
ships its own `libc` and headers. C memory is one USSR vector with C
sizes and alignment, and function pointers go through dispatchers.
pikchr, lemon, tpm, LINPACK and 72/200 of emscripten's `test/core`
match gcc. Limits: no `long double` beyond double, no `-0.0`,
`system()` returns -1, no signals, and the VM limits are 1M
instructions, 1 024 nested calls and 2 billion steps.

## Language coverage
- `setjmp` / `longjmp` (named among emscripten failures)
- Designated initialisers and compound literals in every position
  (check the full C99 grammar)
- Variable-length arrays
- Bit-fields with exact layout
- Flexible array members
- `_Static_assert`, `_Alignof`, `_Alignas`, `_Generic`,
  `_Noreturn`, `_Thread_local` (C11)
- Wide characters and `wchar_t` strings (`L"..."`), plus `u8`/`u`/`U`
  literals
- `_Complex` types
- `inline` semantics and `static inline` in headers
- GNU extensions that real code uses: `__attribute__` (more than
  skipped), statement expressions (present), `typeof`, `__builtin_*`
  (expect, clz, ctz, popcount, offsetof, va_*), case ranges, `?:` with
  an omitted middle
- `#include_next`, `__COUNTER__`, `_Pragma`, `#line` honoured in
  diagnostics
- A 32-bit `long` mode (`-m32`-like) for code that assumes wasm32/ILP32
- Signed or unsigned `char` as an option (`-fsigned-char`)

## Diagnostics
- Warnings: unused variables, implicit declarations, format string
  mismatches, sign compare, shadowing, missing return
- Column numbers and caret lines in errors
- Several errors per run, with recovery, not stopping at the first
- `-Werror`, `-w` and `-Wall` flags

## Optimisation
- Constant folding and propagation across statements
- Register allocation for locals whose address is taken only locally
- Dead code elimination and unreachable code removal
- Inlining of small static functions
- Strength reduction (multiply by a power of two to a shift)
- Peephole passes on the generated bytecode
- Tail-call elimination (helps with the 1 024-call limit)
- `-O0/-O1/-O2` levels and a size report

## Runtime and libc
- More POSIX: `dirent.h`, `sys/stat.h`, `fcntl.h`, `time.h` with real
  clocks, `getenv`/`setenv`, `strtod` accuracy, `qsort` stability notes
- `printf` family completeness (`%a`, `%n`, wide variants), and
  `scanf` completeness
- `system()` through the USSR shell's `run`
- Signals emulated for `raise` / `signal` within the program
- Threads (`threads.h` or a pthreads subset) on the USSR scheduler
- Sockets through the USSR socket API (`sys/socket.h` subset)
- `math.h` precision checked against glibc
- A bounds-checked memory mode (`-fsanitize=address`-like) that catches
  out-of-range indexes into M with the C location

## Tooling
- Separate compilation: `-c` to an object `.ro` file and a linker step,
  for big projects and faster rebuilds
- Static libraries (`.ra` archives) of `.ro` files
- `-S` to print the generated bytecode as UUASM text (docs/USSR_UUASM_SPEC)
- Debug info: line tables in `.ru` so VM errors show `file.c:line`
- A `cc`-compatible driver (flags `-o -I -D -U -l -L -std=`) to drop
  into Makefiles
- `-M` / `-MD` dependency output
- Compile usa with usa? Not C, but compile russia's C runtime parts (the
  self-hosting story)
